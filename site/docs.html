install

❯ curl -fsSL https://portal.cybercorpresearch.com/install.sh | bash

macOS or Linux · zsh · python3 ≥3.8 · fzf ≥0.38, which the installer adds via brew/apt/dnf/pacman if you don't have it. One source line goes into ~/.zshrc; open a new terminal and run portal. Codex sessions are picked up automatically when ~/.codex exists.

the picker

portal lists every past session, newest first. Type and it re-ranks from the first keystroke — BM25 over titles and your prompts, blended with recency, offline, no model. Rows read time · project · title; each project keeps one stable color so you can find it without reading.

typere-rank live (empty = browse by recency)
↵cd to the session's folder and resume it here
⇥mark several — then ↵ sends each to its own shell (fleet)
^Osend the selection to their own shells, even a single one
^Nstart a fresh session in that folder
^Ycopy the launch command instead
^Ereveal collapsed older versions
^/toggle the preview pane
^Rrescan for sessions started since the picker opened

Row markers: ● being written right now · +N near-duplicate reruns collapsed underneath · ⌁ folder has moved (↵ offers to relink).

The preview pane carries the folder, topic chips, the session's arc (first ask → last thing touched), files edited, commits made during the session, related threads in other folders, an activity sparkline, and the model that ran it.

both agents — Claude + Codex

Portal indexes Claude Code transcripts (~/.claude/projects) and OpenAI Codex rollouts (~/.codex/sessions) into one list. Codex files are read the same bounded way: folder, your real prompts (its injected context turns are dropped), model, and token totals — exact, since Codex reports cumulative usage.

  ◇  5h  search   optimize-ranking-heuristics   codex
preview → codex · GPT-5 · 019f7b54 · ~340k tok

Every row wears its agent's mark — Claude in its own coral, Codex in mono — and Codex rows are tagged codex. They flow through search, heavy, grep, and ls --json like any other row. ↵ resumes them with codex resume <id> instead of claude --resume. Nothing to configure.

a fleet — send off to many shells

A plain ↵ jumps into one session in the current shell, same as always. But mark several with ⇥ and ↵ sends each into its own shell — on macOS + Ghostty a real window per agent, colored by that project's theme; inside tmux, a window per agent; elsewhere it prints the commands. ^O does the same for the current pick even if it's just one.

portal watch is the picker, pointed at everything running right now — the same frame, keys, and preview card as portal, but the rows are live agents, auto-refreshing in place. It reads transcripts, so it sees every live agent — whether portal launched it or not — and classifies each from the tail of its log: working (a tool is running), thinking (mid-turn), waiting (turn handed back — needs you), idle. Type to filter the fleet · ↵ jumps into the selected agent · ^O sends it to its own window · esc exits. An open tab is an open agent: any folder with a running claude/codex process keeps its session on the board no matter how long it's been quiet — hours-idle tabs still show as waiting.

What each agent is working on comes in three tiers. Always: the session's own title — the task it's on (fleet cockpit for agents) — with the momentary tool as a dim detail (Bash pytest). With a model configured (below) that headline becomes an agentic one-liner — "reran the eval, waiting on the score" — read from the transcript, not the tool log.

Set PORTAL_NOTIFY=1 and, on macOS, the board posts a silent desktop notification (named to the project) when an agent starts waiting on you — so you can fan out a fleet, walk away, and get pulled back. Off by default; no sound.

The classic full-screen board (no fzf needed) is still there: --interval N runs it at that refresh rate (default 2s) · --once renders a single frame and exits, for scripting.

plain-English status — optional

By default the board shows the mechanical line — state, the session's title (the task), and the tool it's running. It's instant, free, and accurate, and it's what you get out of the box.

If you'd rather have a sentence read from the conversation — "reran the eval, fixing a failing color assertion" — opt in with one env var: PORTAL_MODEL=claude (uses the Claude Code CLI) or =codex (the Codex CLI), or PORTAL_MODEL_URL=http://localhost:11434/v1 for a local OpenAI-compatible model (Ollama, LM Studio — cheapest, no tokens). Summaries compute in the background, cache, and throttle to ~once/20s per agent, and the transcript is fed as data, never instructions.

project colors — your Ghostty themes

Every project maps deterministically to one of Ghostty's own bundled themes — the same project always gets the same one. The board tints its row with a vivid, contrast-checked accent from that theme, and a dispatched window is that theme, so the color on the board and the window on screen are one thing. No random pastel wash; where Ghostty's themes aren't present it falls back to a muted hue-hash.

commands

portal go "…" — jump without the picker

❯ portal go "the webhook retry fix"
◇ teleport ~/code/acme/billing (0.94)
▸ resume f4e9b2c1 — fix-webhook-retry-loop

Ranks headless. A confident match cds in and resumes; anything ambiguous opens the picker pre-filtered rather than guessing.

portal pull "…" — bring a session here

❯ cd ~/code/acme/gateway
❯ portal pull "auth refactor"
◇ pulled refactor-auth-middleware → here
▸ resuming forked — original untouched

Copies the transcript into the current folder and resumes it with --fork-session. --move relocates instead of copying.

portal mv <src> <dst> — move a folder and its history

❯ portal mv ~/code/acme/api ~/code/platform/api
◇ moved folder → ~/code/platform/api
  ✓ session a1b2c3d8 migrated

Claude Code keys transcripts to the folder path, so a plain mv strands them. This moves the folder and migrates every session with it, rewriting paths and preserving timestamps.

recipes

standup — everything you touched in 24h, newest first:
portal ls --json | jq -r '[.[] | select(now - .mtime < 86400)] | sort_by(-.mtime)[] | "\(.project) \(.title)"'
shutdown guard — one line in your logout hook:
portal status | grep -q unpushed && echo "don't close yet"
orphan sweep — after a reorg:
portal ls --json | jq -r '.[] | select(.orphan) | .title' then portal doctor

configure

Portal launches Claude with no extra flags. Set your own in ~/.zshrc above the source line:

PORTAL_FLAGS=(--dangerously-skip-permissions --chrome)
export PORTAL_CODE_ROOT=~/code   # where doctor and fresh-dir suggestions look
export PORTAL_BANNER=compact     # header: compact (default, one line) · full (ANSI-Shadow art) · off
export PORTAL_MODEL=claude       # optional watch narration: claude · codex · a local URL (default: off)
export PORTAL_NOTIFY=1            # silent desktop notify when an agent needs you (default: off)
export PORTAL_WATCH_WINDOW=45     # quiet-minutes cutoff for sessions WITHOUT a running process (open tabs always show)
export PORTAL_NO_PROC=1           # skip the ps+lsof open-process scan (constrained machines)

The header is a single line by default so the session list starts right at the top; set PORTAL_BANNER=full for the ANSI-Shadow PORTAL art (the same as this site), or off for none. Light and dark terminals are detected automatically; the picker is monochrome either way, apart from project colors and each agent's mark.

how it works

index.py reads ~/.claude/projects/*/*.jsonl — and ~/.codex/sessions when it exists — pulling each session's folder, title, prompts, model, and usage out with bounded head+tail reads, then caching a compact index. rank.py is the search brain; fzf is a dumb renderer driven per keystroke via change:reload. Pure python + zsh + fzf, no dependencies, fully offline.

Nothing is written back to your transcripts except by mv, pull, and doctor, which stream atomically and preserve timestamps.

uninstall

❯ rm -rf ~/.claude/portal   # then drop the source line from ~/.zshrc

Your transcripts in ~/.claude/projects are never touched.
